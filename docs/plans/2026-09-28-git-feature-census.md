# Pinned Git feature census

A reproducible high-water mark comes from pinned Git source, not the host Git version
or the historical 44-row table. Keep command coverage, documented option/term surface,
parser exposure, historical declarations and behavioral proof separate. Unknowns and
intentional differences stay visible. This does not promise all Git behavior is a goal.

- [ ] Extract pinned command categories and documented feature terms/options with expanded local includes, exact source locations, and explicit unsupported extraction constructs; stable JSON plus human summary and non-writing freshness check.
- [ ] Export the real compiled Brit Clap surface and compare it against the pinned inventory, preserving separate declared/parsing/unverified dimensions and native-only commands.
- [ ] Gate determinism, reference drift, parser edge cases, mapping honesty and report freshness in CI; independently review and record local evidence without asserting full behavioral parity.

Classification: inventory and comparison are ephemeral derived views (C) of versioned
source declarations. Stable feature IDs are human-readable source anchors, not new
participant or content identities. No DHT entries, protocol encoder or network authority.

An intentionally unimplemented command is a terminating boundary edge: declare its
owning subsystem, reason, alternative/bridge, and reconsideration condition. Preserve
undecided, planned, deferred and intentional exclusion as distinct states; never
infer intentional exclusion from missing code. All nodes remain in the reference
denominator. Proposed policy does not masquerade as an approved boundary decision.
