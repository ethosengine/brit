# Brit compatibility policy as a Mishpat lens

Recall this concern as **Mishpat policy judgment informed by Middot**, not merely
as the Git census script. The census and parser comparison are observation
procedures. Their results inform which capabilities Brit should implement,
prioritize, bridge, intentionally differ on, or exclude. Policy ownership and
adoption remain a distinct act. A percentage never grants authority by itself.

This document records the native framing and integration contract. Brit-local measures now record reconciled magnitudes through the native observation
interface using an explicit registry. This does not claim that a lens has been
ratified or that either readiness marker is green.

## The measures and their subjects

The proposed measure family is Git compatibility. Preserve these dimensions rather
than reducing them to one score:

| Middah / observation | Subject and reproducible procedure | Unit and evidence limit |
| --- | --- | --- |
| Reference feature inventory | Immutable Git commit plus exact extractor bytes; census.py and atoms.py | Commands, context groups, spellings, verb candidates and extraction diagnostics stay separate |
| Public parser exposure | Pinned reference inventory plus exact Brit executable, parser export and comparator bytes | All/some/no spelling matches and unresolved forms; no behavioral inference |
| Public behavioral conformance | Brit executable against a versioned Git oracle and identified test cases | Legacy assertion receipts now joined as candidate evidence, preserving exit-only, normalized-output, failed, skipped and unmeasured distinctions; full conformance remains incomplete |
| Inherited engineering discipline | Exact integration revision, required feature/platform legs and CI evidence | Qualified/unqualified/missing legs; upstream green alone does not qualify fork changes |
| Native daily-driver acceptance | Declared workflow stations, gates, delivery and independent developer trials | Accepted/unaccepted/unmeasured station evidence; independent of maximal Git coverage |

A registered measure must name its version, family, unit, procedure, lineage and
environment sensitivity. A reusable result must bind the subject, exact method and
environment to the result and provenance. Host/platform, build presets and oracle
version matter where the method depends on them. Record unknown inputs as unknown;
a source HEAD cannot attest dirty executable bytes. Count changes caused by a
corrected extractor require method lineage, not an unexplained progress claim.

The foundational design is *Middot — the Measure Primitive (Honest Weights and
Measures over EPRs)*, with *Plural Mishpat Lenses over EPR* defining plural reading
contexts. Both live in the Elohim repository's genesis/docs/superpowers/specs;
these are protocol design references, not standalone Brit runtime dependencies.
The measures stay observational. Claimed, independently witnessed and accepted
results retain their distinct evidence standing.

## The Mishpat lens

A Brit compatibility lens consumes those measures against its declared purpose and
responsibility boundary. Two readings can coexist over the same observations:

- **Daily-driver:** which required workflows have sufficient safety, enforcement,
  interoperability, delivery and recovery evidence for the intended developers?
- **Maximal Git comparison:** where does Brit align, diverge, delegate or stop
  across the pinned reference graph, without shrinking that reference?

A policy decision names its owner, subject node, evidence, reason, disposition,
alternative, adoption state and reconsideration condition. The current command
boundary file enforces the basic reason/owner/alternative/reconsideration fields;
native measure observations now exist, but binding an adopted decision to its
chosen evidence remains work.
Command decisions inherit to descendant groups; option-specific governance is not
yet implemented. A high parser-match ratio cannot compensate for a missing gate,
and a deliberate exclusion is a visible boundary rather than a disappearing node.

Prioritization belongs to the consuming lens: workflow importance, risk, dependency
order, current evidence and upstream ownership can inform it. No weights, hard
thresholds or cutover authorization are adopted by this framing. Gix's upstream
scope is respected; Brit's policy cannot assign obligations to gix maintainers.

## Recall contract

A developer or agent should be able to ask “which Middot support Brit's Mishpat
compatibility decision?” and find this concern by its declared tags and title.
Then follow the existing authorities:

- [Census usage and atomic walks](README.md): procedures and current limitations.
- [Capability boundaries](capability-boundaries.md): gix/Brit ownership and markers.
- [Command boundary decisions](../../.epr-meta/git-boundaries.json): authored choices.
- [Compatibility habit](.epr-meta/brit-git-compatibility.habit.md): evidence ledger.
- [Inherited readiness contract](../../.epr-meta/readiness.json): required CI legs.

Recall must return the lens/measure version and input identities with a saved
measurement; a stale fold is historical evidence, never a fresh readiness verdict.
A recall hit establishes discoverability only. It does not establish approval,
ratification, or whether a measurement has been independently witnessed.

Today, the parent Elohim governed recall executor can discover this artifact through
its `mishpat` and `middot` tags and verify its current source. Standalone Brit still
lacks the recall algorithm package. The native reader defaults to the legacy
`.claude/epr-meta/` registries, but its existing `--measures` override now explicitly
consumes Brit's [local registry](../../.epr-meta/measures.yaml). The observe adapter
re-reconciles original receipts against current sources before recording through
`epr flow note`. It binds the report subject, registry, method and receipt set and
keeps assertion strength/status/freshness as separate environment dimensions.

These are claimed observations, not independently witnessed test executions or
policy rulings. The local sidecar preserves their native records; the recallable
[reconciliation report](../plans/task-parity-reconcile-3-report.md) names the run,
limitations and evidence. The registry is not automatically discovered and declares
no acceptance thresholds. A portable recalled lens with explicit adopted bindings
is still an integration frontier; use the existing native machinery to close it.
